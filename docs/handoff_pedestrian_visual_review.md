# 行人行为视觉核实任务（交接视觉模型）

> **SUPERSEDED — 2026-08-04**：本文的“单帧 A/B/C 判断”不能可靠识别运动方向，且其“measurements 不记录行人”前提错误。后续以 `measurements.is_pedestrian_present` 的 AutoPilot 轨迹碰撞真值与连续语义可见帧对齐；结果见 `results/thesis_m1/pedestrian_hazard_visibility_20260804.json`。下方清单仅保留为历史索引，不再执行人工 A/B/C 回填。

## 1. 任务

判断以下 584 个 sequence 里的行人属于哪种：
- **A. jaywalker（冲入车道）**：行人从路边/人行道进入或朝车道移动，构成驾驶威胁
- **B. 正常走（人行道）**：行人在人行道上，不进入车道
- **C. 不确定**：看不清/被遮挡/距离太远

## 2. 背景（为什么需要这个判断）

H1 交通域视觉预训练实验里，行人(pedestrian)只在 584/9968（5.9%）的 sequence 出现，像素占比仅 0.011%。项目假设这些行人都是"从路边冲入车道的 jaywalker"（CARLA Leaderboard 场景定义的行人穿越）。需要视觉确认这个假设：
- 如果绝大多数是 A（jaywalker）：当前数据是高危场景样本（稀缺但高价值），改进方向是补采更多同类场景
- 如果多为 B（正常走）：这些行人对驾驶决策价值低，需要重采真正的 jaywalker 场景

## 3. 数据位置

数据根：`/data1/shijj/interfuser_data/`
每个 sequence 含 `rgb_front/left/right`（RGB 图像）+ `seg_front/left/right`（语义 mask，pedestrian = tag 12）+ `depth_*` + `lidar` + `measurements` + `other_actors`。
**注意**：other_actors 只记录 vehicle 和 traffic_light，不记录行人 actor；measurements 只记录 ego 车辆。所以行人行为无法从元数据判断，必须看 RGB。

## 4. 判断标准

看 `rgb_front/left/right` 里行人 actor 的位置和运动方向：
- **A jaywalker**：行人在车道上，或从人行道横向移动进入车道（运动方向朝车道）
- **B 正常走**：行人在人行道/路边，沿人行道方向运动，不进入车道
- **C 不确定**：距离太远/被遮挡/帧里行人像素太少无法判断
